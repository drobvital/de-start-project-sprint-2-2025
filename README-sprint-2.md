# Проект 2-го спринта: интеграция нового источника в DWH + витрина заказчиков

## 📋 Описание проекта

Маркетплейс товаров ручной работы приобрёл конкурирующий сайт. Данные нового источника нужно интегрировать в существующее хранилище (DWH) и построить витрину отчётности по заказчикам для запуска программы лояльности.

## 🎯 Бизнес-задача

Витрина `customer_report_datamart` — ежемесячный отчёт по каждому заказчику: траты, доход платформы (комиссия 10%), количество заказов по статусам, средний чек, медианное время выполнения заказа, топовая категория товаров и самый популярный мастер. Используется для программы лояльности и рекомендательной системы.

## 🏗 Архитектура решения

```
source1 (широкая таблица)          ─┐
source2 (2 денормализованные табл.) ─┼→ dwh: измерения + факты ─→ customer_report_datamart
source3 (3 нормализованные табл.)  ─┤   (d_customer, d_product,      (инкрементальный расчёт
external_source (новый источник)   ─┘    d_craftsman, f_order)         за отчётный период)
```

## 📁 Структура проекта

```
scripts/
├── DDL_customer_report_datamart.sql           # DDL витрины заказчиков
├── DDL_load_dates_customer_report_datamart.sql # Таблица дат загрузки (контроль инкремента)
├── DDL_tmp_sources.sql                        # Временные таблицы объединения источников
├── DDL_tmp_sources_fact.sql                   # Временная таблица фактов
├── DML_merge_d_customer.sql                   # MERGE измерения заказчиков
├── DML_merge_d_product.sql                    # MERGE измерения товаров
├── DML_merge_f_order.sql                      # MERGE таблицы фактов заказов
├── DML_update_dwh_d_craftsman.sql             # Обновление измерения мастеров
└── SQL_increment_datamart.sql                 # Инкрементальный расчёт витрины
```

| Модель данных | Измерения + факты |

## 📊 Логика витрины

- **Комиссия платформы:** 10% от суммы покупок заказчика за месяц
- **Статусы заказов:** создан / в изготовлении / в доставке / завершён — отдельными агрегатами
- **Медианное время выполнения заказа:** от создания до завершения, в днях
- **Топовая категория и мастер:** по количеству заказов заказчика за отчётный период
- Витрина инкрементальная: пересчитывается только за новые периоды (контроль через таблицу дат загрузки)

## 📚 Что изучил

- Интеграция нового источника в существующее DWH без остановки загрузок
- Объединение источников с разной структурой (нормализованные и денормализованные) через временные таблицы
- Инкрементальное обновление витрин
- Продвинутый SQL: MERGE, оконные функции, расчёт медианы, условные агрегаты
